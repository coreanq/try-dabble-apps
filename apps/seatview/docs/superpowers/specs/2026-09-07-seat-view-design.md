# 좌석 시야 3D 미리보기 웹앱 — 설계 문서

작성일: 2026-09-07
상태: 사용자 승인 완료 (브레인스토밍 세션)

## 1. 목적

콘서트·공연장 좌석을 고르면 그 자리에서 무대가 어떻게 보이는지 3D로 보여주는 웹앱.
여러 공연장을 지원하는 일반 서비스이며, 공연장 추가가 쉬운 구조를 최우선으로 한다.

## 2. 범위

### 포함
- 공연장 목록 → 2D 좌석도 → 개별 좌석 클릭 → 3D 시야
- 개별 좌석 번호 단위(구역·열·번호)까지 구분
- 시야 내용: 공연장 구조(관중석, 단차, 기둥·난간 등 방해물) + 기본 무대 위치·크기
- 공연장 데이터를 만드는 관리자용 디지타이징 도구
- 공개 도면이 있는 공연장은 Blender로 만든 외형(glb)을 선택적으로 얹음

### 제외 (이번 버전)
- 공연 일정 (추후 KOPIS 공연예술통합전산망 API로 "공연 → 공연장" 매핑만 추가 예정)
- 공연별 무대 세트(돌출무대, 스크린 등)
- 실사 수준 렌더링(조명, 재질, 관객)
- 백엔드/DB, 사용자 계정, 사진 업로드
- 티켓 사이트 자동 크롤러. 좌석배치도 이미지는 1회 수동 저장하여 도구에 입력
- 좌석도 이미지 자동 인식

## 3. 3D 데이터 확보 정책

1. 인터넷에서 해당 공연장의 공개 도면·단면도·치수를 먼저 조사한다.
2. 도면이 충분하면 Blender로 외형(벽·지붕·기둥) glb를 제작한다. 원점은 반드시 "무대 중앙 바닥".
3. 도면이 없으면 2D 좌석배치도만으로 파라미터 정의를 만든다(외형 없음).
4. 어느 경우든 관중석·좌석은 파라미터에서 자동 생성한다. 외형 glb는 덧붙임일 뿐이다.

## 4. 아키텍처

세 가지 구성 요소. 모두 하나의 코드베이스(Vite + TypeScript + three.js), 정적 호스팅.

| 구성 요소 | 역할 | 사용자 |
|---|---|---|
| 뷰어 (`/`) | 공연장 목록, 2D 좌석도, 3D 시야 | 일반 사용자 |
| 공연장 정의 JSON | 구역 파라미터, 무대, 방해물, 외형 glb 경로 | 뷰어·도구가 공유 |
| 디지타이징 도구 (`/admin`) | 좌석도 이미지 위에 구역을 그려 JSON 생성, 3D 즉시 미리보기 | 관리자 |

- 서버 로직 없음. `public/venues/index.json`(목록)과 `public/venues/<id>/venue.json`, 선택적 `shell.glb`만 서빙한다.
- 도구는 뷰어의 좌석 생성·3D 렌더링 코드를 그대로 재사용한다.
- UI 프레임워크 없이 최소 DOM으로 시작한다.

### 모듈 경계

| 모듈 | 책임 | 의존 |
|---|---|---|
| `venue-schema` | JSON 타입 정의 + 검증 | 없음 |
| `seat-engine` | 구역 파라미터 → 좌석 목록(id, position) 계산. 명시 좌표 구역 처리 포함 | venue-schema |
| `venue-mesh` | 좌석 목록·무대·방해물 → three.js 메시 (InstancedMesh) | seat-engine, three |
| `seat-camera` | 좌석 id → 카메라 위치·시선. 인접 좌석 탐색 | seat-engine |
| `seatmap-2d` | 평면 좌석도 캔버스, 클릭 → 좌석 id | seat-engine |
| `viewer-app` | 라우팅, 화면 조합, URL 상태 | 위 전부 |
| `admin-app` | 배경 이미지, 스케일 캘리브레이션, 구역 편집 UI, JSON 내보내기 | 위 전부 |

`seat-engine`은 three.js에 의존하지 않는 순수 함수 모듈로 두어 단위 테스트를 쉽게 한다.

## 5. 데이터 모델 (venue.json)

단위: 미터. 원점: 무대 중앙 바닥. Y가 위, 무대가 바라보는 방향이 +Z.

```jsonc
{
  "id": "kspo-dome",
  "name": "KSPO DOME (올림픽체조경기장)",
  "units": "m",
  "stage": {
    "center": [0, 0, 0],
    "size": [20, 1.2, 12],           // 폭, 무대 바닥 높이, 깊이
    "facing": [0, 0, 1]
  },
  "sections": [
    {
      "id": "A",
      "label": "A구역",
      "shape": { "type": "arc", "center": [0,0], "radiusStart": 25, "angleStart": -30, "angleEnd": 30 },  // center는 [x, z], 각도는 도 단위, 0도 = +Z
      "rows": 20,
      "rowDepth": 0.9,                // 열 간격
      "riser": 0.35,                  // 열당 높이 상승
      "baseHeight": 0.0,              // 1열 바닥 높이
      "seatsPerRow": 40,              // 숫자 또는 열별 배열
      "rowLabels": "numeric",         // "numeric" 또는 문자열 배열
      "seatNumbering": "left-to-right" // 또는 "right-to-left"
    },
    {
      "id": "2F-201",
      "shape": { "type": "polygon", "points": [[-30,40],[-10,40],[-10,55],[-30,55]] },
      "rows": 12, "rowDepth": 0.85, "riser": 0.45, "baseHeight": 8.0,
      "seatsPerRow": 22
    },
    {
      "id": "BOX-3",
      "shape": { "type": "explicit" },
      "seats": [
        { "row": "1", "seat": 1, "position": [-22, 6.5, 33] }
      ]
    }
  ],
  "obstacles": [
    { "type": "pillar", "position": [-12, 0, 30], "radius": 0.4, "height": 12 },
    { "type": "railing", "from": [-30, 8, 40], "to": [-10, 8, 40], "height": 1.0 }
  ],
  "shell": { "glb": "/venues/kspo-dome/shell.glb" }   // 선택
}
```

### 규칙
- 좌석 좌표는 저장하지 않는다. `section + row + seat` → 위치는 `seat-engine`이 계산한다.
  - arc: 각도 범위를 좌석 수로 등분. 열마다 반경을 `rowDepth`씩 늘리고 높이를 `riser`씩 올린다.
  - polygon: 첫 두 점을 잇는 변을 "앞변"으로 보고 등분. 열마다 앞변의 법선 방향으로 `rowDepth`씩 밀고 `riser`씩 올린다.
  - explicit: `seats` 배열을 그대로 쓴다. 파라미터로 표현 안 되는 구역(장애인석, 박스석)에만 사용.
- 카메라 = 좌석 위치 + 앉은 눈높이 1.2 m, 무대 중앙을 향한다.
- `shell.glb`가 있으면 외형만 그 모델을 쓰고 관중석·좌석은 여전히 파라미터에서 생성한다.
- 열당 좌석 수가 다르면 `seatsPerRow`를 배열로 준다. 그래도 안 맞으면 구역을 쪼갠다.

### 저장 이유 (파라미터 vs 좌표)
- 좌석 1만 5천 석 공연장도 구역 40~60개 입력으로 끝난다.
- 좌석도 이미지에는 구역·열 수·열당 좌석 수까지만 있고 실제 미터 위치는 없다. 개별 좌표를 찍어도 "균등 배치" 가정으로 만든 값이 된다.
- 단차 수정 같은 보정이 숫자 하나로 끝난다.

## 6. 디지타이징 도구 작업 흐름

사전 준비(도구 밖):
1. 티켓 사이트에서 좌석배치도 이미지 저장(층별).
2. 공연장 도면·치수 검색. 실측 숫자 1~2개(무대 폭, 객석 최대 거리 등)가 스케일 기준.
3. 도면이 충분하면 Blender 외형 glb 제작(원점 = 무대 중앙 바닥).

도구 안(`/admin`):
4. 배경 이미지 올리기. 알고 있는 실제 거리 두 점을 찍어 픽셀→미터 비율 지정. 무대 중앙 클릭으로 원점 지정.
5. 무대 사각형 드래그, 객석 쪽 클릭으로 방향 지정.
6. 구역 그리기: 다각형 클릭 또는 호 핸들 조정. 우측 패널에서 열 수·열당 좌석 수·열 간격·단차·시작 높이 입력.
7. 하단 3D 미리보기가 항상 켜져 있고 구역 저장 즉시 반영. 좌석 클릭으로 시야 확인.
8. 층 전환: 배경 이미지 교체, `baseHeight`를 층 높이로 두고 반복.
9. 방해물(기둥·난간) 클릭으로 추가.
10. 좌석 수 합계 표시(티켓 사이트 총석수와 대조) 후 JSON 다운로드. `public/venues/<id>/venue.json`에 배치.

- 작업 중 상태는 localStorage에 임시 보관.
- 예상 소요: 이미지 준비 후 공연장당 1~2시간. 외형 glb는 별도 며칠.

## 7. 뷰어 화면 흐름

1. `/` 공연장 목록: 이름, 좌석 수, 외형 모델 유무. `venues/index.json` 로드.
2. `/#/v/<venueId>` 좌석도: 좌측 2D 평면(구역 클릭 → 확대 → 좌석 클릭), 우측 3D. 모바일은 상하 배치.
   - URL에 좌석 유지: `/#/v/kspo-dome?s=A&r=12&n=7` 로 공유 가능. 정적 호스팅에서 서버 fallback 설정 없이 동작하도록 해시 라우팅을 쓴다.
3. 3D 시야: 좌석 클릭 시 카메라 부드럽게 이동. 마우스/터치 둘러보기. FOV 슬라이더. 하단에 무대까지 거리(m)와 층·구역·열·번호. 인접 좌석 이동 버튼(앞/뒤/좌/우).
4. 텍스트 검색: "A구역 12열 7번" 입력으로 이동.

## 8. 오류 처리

| 상황 | 동작 |
|---|---|
| venue.json 없음/파싱 실패/스키마 불일치 | 목록으로 돌아가는 오류 화면 |
| shell.glb 로드 실패 | 외형 없이 파라미터 관중석만 표시 + 작은 안내. 서비스 계속 |
| URL의 좌석이 없음 | 좌석도는 열고 "좌석을 찾을 수 없음" 표시 |
| WebGL 미지원 | 2D 좌석도만 표시 + 안내 |

## 9. 테스트·검증

- 단위 테스트(Vitest), `seat-engine` 중심:
  - 구역 파라미터 → 좌석 수 합계
  - 첫 열·마지막 열 높이(`baseHeight`, `riser` 적용)
  - arc 구역 좌석 간 각도 등분
  - polygon 구역 앞변 등분과 법선 방향 후퇴
  - explicit 구역 그대로 통과
  - `seatsPerRow` 배열 처리
  - 잘못된 파라미터(rows 0, 배열 길이 불일치, 미지원 shape) 거부
  - JSON 스키마 검증
  - `seat-camera` 인접 좌석 탐색(구역 경계에서 null)
- 시각 검증(수동): 샘플 공연장 1곳 완성 후 실제 관객 후기 사진 3장과 같은 좌석의 3D 시야를 나란히 비교. 각도·거리감 일치가 "시야가 맞다"의 기준.
- 성능: 1만 5천 석을 중급 스마트폰에서 30 fps 이상. 좌석은 InstancedMesh 하나로 그린다.

## 10. MVP 범위

- 뷰어 + 디지타이징 도구 + seat-engine
- 샘플 공연장 1곳(외형 glb 없이 파라미터만)으로 목록 → 좌석도 → 시야까지 동작
- shell.glb 로더는 구현하되 실제 모델 제작은 별도 작업

## 11. 알려진 제약

- 티켓 사이트 좌석도는 이미지/canvas라 구조화 데이터를 주지 않는다. 수동 디지타이징이 전제다.
- 파라미터 생성은 근사치다. 비정형 구역은 쪼개거나 explicit로 처리한다.
- 실제 시야 정확도는 스케일 캘리브레이션과 단차 입력값에 좌우된다. 후기 사진 비교로 보정한다.

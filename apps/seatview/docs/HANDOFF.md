# SeatView 인수인계 (2026-09-08)

다른 세션에서 이어서 작업하기 위한 요약. 상세는 `docs/superpowers/specs/2026-09-07-seat-view-design.md`(설계)와 `docs/superpowers/plans/2026-09-07-seat-view-mvp.md`(구현 계획, 18개 태스크 전부 완료).

## 현재 상태

- MVP 완성, 이 폴더(`apps/seatview`)가 배포용 원본. 로컬 사본 `D:\lsis\1git\test\seatview`는 같은 내용이며 더 이상 갱신하지 않아도 됨.
- `npm run dev` → `/` 뷰어, `/admin/` 디지타이징 도구. `npm test` 102개, `npm run build`, `npm run deploy`(wrangler, seatview.try-dabble.com, 아직 배포 안 함).
- 데이터는 샘플 아레나(가상, 2,888석)뿐. 실제 공연장 없음.
- 구조: `src/core`(순수 계산, 테스트 대상) / `src/three`(렌더링) / `src/ui`(2D 좌석도) / `src/viewer` / `src/admin`. 좌표계: 미터, 원점 무대 중앙 바닥, Y 위, 관중석 +Z, arc 0° = +Z.

## 사용자가 정한 것 (반드시 지킬 것)

- 좌석 좌표는 저장하지 않고 구역 파라미터(arc / polygon / explicit)에서 계산한다. 비정형 좌석만 explicit.
- 3D 외형(`shell.glb`)은 공연장별로 나중에 입힌다. 코드는 이미 로더와 실패 시 안내를 갖추고 있다.
- 실사 사진 워크플로: 어느 좌석에서 찍었는지 아는 사진은 그 좌석 시점에 3D를 겹쳐 검증·보정에 쓴다. 좌석을 모르는 사진은 Blender 작업 때 좌석·무대·재질 참고용으로만 쓴다. 저장 위치 제안: `public/venues/<id>/refs/` + `refs.json` `{ file, seat?: {s,r,n}, note }`. 실데이터가 생길 때 구현.
- Blender MCP 워크플로(미구현): venue.json으로 관중석 단·무대를 Blender에 생성 → 사진 좌석 위치에 카메라 + 사진을 배경 이미지로 → 벽·지붕·세트 모델링 → 원점 규칙대로 `shell.glb` 내보내기.
- 사용자는 브레인스토밍 질문을 길게 이어가는 것보다 짧은 제안 후 "진행" 확인을 선호한다. 태스크마다 스펙 검토 + 코드 품질 검토를 거치는 서브에이전트 방식으로 구현했고 만족했다.

## 다음 작업: 모바일 UX (설계 승인 대기 중, 사용자가 긍정적)

1. 800px 이하/터치 기기에서 화면 전환 방식: 좌석도 전체 화면 → 좌석 선택 시 3D 전체 화면 + 하단 시트(좌석명, 거리, 앞/뒤/좌/우, 공유, 자이로), "◀ 좌석도" 버튼. 렌더러는 재생성하지 않고 보이기/숨기기.
2. 제스처: 좌석도 핀치 줌·더블탭, 3D 핀치로 시야각 30~100°, 데스크톱은 휠로 시야각.
3. 자이로 둘러보기 버튼(iOS는 버튼 눌렀을 때 권한 요청).
4. 터치 목표: 좌석 점 최소 지름 12px, 탭 허용 반경 16px.
5. 구역 ▸ 열 ▸ 번호 드롭다운 선택(데스크톱 헤더에도).
6. 공유 버튼(Web Share API, fallback 클립보드).
7. 성능: 터치 기기 픽셀 비율 1.5, 3D는 변경 시에만 렌더.
8. PWA: manifest + 아이콘, `vite-plugin-pwa`로 앱 셸 캐시, 본 venue.json 캐시, glb는 본 것만 상한 두고 캐시, 새 버전 배너, `/admin/`은 캐시 제외, iOS 설치 안내 문구.

제외: 좌석도 회전, 3D 안 좌석 클릭, 오프라인 완전 지원.

## 알려진 후속 과제

- 핀치 줌 없음(현재 휠만), 15k석 30fps 실측 안 함, `/admin/` 무인증 공개(로컬 저장·다운로드만이라 위험 낮음), `disposeVenueGroup`이 glb 텍스처는 해제하지 않음, `venue-list`가 목록마다 venue.json을 전부 받음(공연장 많아지면 index.json에 좌석 수 넣기).
- 스펙 §9 검증(관객 후기 사진 비교)은 실제 공연장 데이터가 있어야 가능.
